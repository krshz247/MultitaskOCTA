# Claims table — every number that may appear on a CV, LinkedIn or the README

Status values: **thesis-printed** (printed in the thesis PDF; page = printed page / PDF page) · **re-run in this repo** (produced by code in this repository; source file and commit given) · **carried over from a doc** (stated in a doc, not checkable from committed files) · **hypothesis** (no experiment tests it).

**Like-for-like comparison:** the thesis' 95.2 % is an *accuracy*, so the only comparable re-run number is *accuracy*: about 0.79–0.82 (joint model). It is still not the same protocol (the thesis' split is not described; the re-run uses stratified cross-validation with held-out test folds). Balanced accuracy (0.76) is **never** to be compared with the thesis' 95.2 %; the thesis reports no balanced accuracy. The class imbalance (251 Normal / 64 DR / 49 AMD) makes accuracy higher than balanced accuracy.

## 3. Rules for use
- Never put a thesis number and a re-run number in one sentence without naming both metrics and both protocols.
- State accuracy and balanced accuracy separately; never quote 0.75–0.77 next to 95.2 %.
- Claims marked hypothesis stay out of CV and LinkedIn text.
- When a number changes (seed 3 of the shuffled-mask and classification-only recipes is pending), update this table in the same commit as the result.
